# PRD：zpaper — Claude Code 文献管理与阅读助手

**版本**：1.0
**日期**：2026-05-05

---

## 问题陈述

在 Claude Code 中工作的个人研究者缺乏结构化的文献管理工具。PDF 散落在不同文件夹，论文之间的关联需要手动维护，阅读笔记没有固定归宿。Mendeley、Zotero 等现有工具依赖 GUI 交互，会打断深度工作的心流。不解决这个问题的代价：已读论文的知识无法被沉淀和关联，写综述时需要重新翻找已经看过的内容。

---

## 目标

1. **零摩擦导入**：粘贴一个 arXiv ID 即完成导入，元数据自动获取，PDF 自动下载。85% 以上的标准学术 PDF 可自动提取完整元数据。
2. **5 分钟内可检索的文献库**：跨标题、摘要、关键词和笔记的全文检索，不需要在文件夹里翻找。
3. **结构化阅读输出**：总结和精读模式产出结构化 Markdown，用户可直接复用于写作。目标：60% 以上的生成摘要被保存为笔记。
4. **有溯源的笔记**：每条笔记绑定论文 ID 和时间戳，可跨库检索。
5. **零 GUI 依赖**：所有功能通过 Claude Code 自然语言或 `/paper` 命令完成，无需打开其他应用。

---

## Non-Goals（明确不做）

- **不做多人协作**：单用户工具，不支持共享、权限管理或同步。
- **不做云端存储**：数据全部存本地，无账号系统。
- **不做 GUI 客户端**：不开发桌面或 Web 界面，Claude Code 就是交互界面。
- **不做引用格式化**：不输出 APA/MLA/Chicago 格式引用（存储原始元数据，格式化不在范围内）。
- **不做 PDF 标注同步**：笔记存在系统自己的数据库中，不嵌入 PDF 文件，不与 PDF 标注应用同步。

## 用户故事

### 导入与管理
- 作为研究者，我希望说"添加 arXiv:2301.12345"后论文元数据和 PDF 自动入库，这样我不需要手动复制粘贴标题和作者。
- 作为研究者，我希望在 Claude Code 内直接搜索 arXiv 并导入论文，这样我在工作中途不需要切换到浏览器。
- 作为研究者，当元数据提取失败时，我希望明确看到哪些字段缺失，而不是留下一条静默的残缺记录。

### 阅读
- 作为研究者，我希望在 60 秒内得到任意论文的结构化摘要，这样我可以在精读之前判断是否值得深入。
- 作为研究者，我希望在 Claude 的引导下逐节阅读论文，每节后有提问检验理解，这样我能真正消化而不是走马观花。
- 作为研究者，我希望阅读途中随时添加笔记，笔记自动关联当前论文，这样我的想法能被及时记录。

### 发现与综述
- 作为研究者，我希望问"和这篇论文相关的文献有哪些"并得到有理由的列表，这样我能追溯一个想法的学术脉络。
- 作为研究者，我希望说"帮我写一篇关于主题 X 的综述"并得到引用我文献库的草稿，这样我有一个文献综述章节的起点。

## 需求

### Phase 1 — 导入与搜索（P0）

| 需求 | 验收标准 |
|---|---|
| 本地 PDF 导入 + 自动元数据提取 | 标准学术 PDF 的 title/authors/year 提取成功率 ≥85% |
| arXiv 导入：获取元数据 + 下载 PDF | 给定 arXiv ID，30 秒内完成导入，元数据完整 |
| 从 CLI 搜索 arXiv | 返回按相关性排序的结果，包含标题、作者、年份、摘要片段 |
| 全文库检索 | 关键词查询返回相关论文，按相关性排序 |
| SQLite 本地数据库 | 所有数据存于 `~/.scholarmind/library.db`，原始 PDF 不被修改 |
| `/paper` 命令族 | `add`、`search`、`web-search`、`list`、`show`、`tag`、`delete`、`config` |

### Phase 2 — 阅读与笔记（P0）

| 需求 | 验收标准 |
|---|---|
| 总结模式 | 从 PDF 全文生成 5 节结构化摘要 |
| 精读模式 | PDF 按检测到的章节切分，Claude 逐节引导，每节后提问 |
| 笔记创建 | 笔记绑定论文 ID 并记录时间戳 |
| 跨库笔记检索 | 关键词检索返回匹配笔记及其论文上下文 |
| Markdown 导出 | 论文笔记可导出为带 frontmatter 的标准 Markdown |
| 阅读状态追踪 | 论文可标记为 unread / reading / read |

### Phase 3 — 发现与综述（P1）

| 需求 | 验收标准 |
|---|---|
| 相关论文查找 | 返回最相关的 N 篇论文，附相似度解释 |
| 文献网络模式 | 以文本形式输出时间线和自动检测的关联，供 Claude 分析 |
| 综述模式 | Claude 生成结构化综述草稿，含行内引用 |
| 主题聚类 | `graph <主题>` 和 `survey <主题>` 可按主题筛选相关论文 |

### 未来规划（P2）

- **MCP Server**：将文献库封装为 MCP tools，供其他 Claude 实例调用
- **Obsidian 同步**：笔记导出为 Obsidian 兼容 Markdown，含双向链接
- **本地向量检索**：基于本地嵌入模型（如 nomic-embed）的语义搜索
- **阅读进度追踪**：记录每篇论文的阅读时长和笔记密度

## 技术栈

| 组件 | 方案 | 理由 |
|---|---|---|
| 数据存储 | SQLite（`~/.scholarmind/library.db`） | 无服务器、全本地、Python 原生支持 |
| PDF 解析 | `pymupdf`（fitz） | 对学术 PDF 双栏布局支持最好 |
| 元数据补全 | arXiv API（免费，无需 Key） | 覆盖 CS/物理/数学大部分论文 |
| 网络搜索 | Claude Code 内置 `web_search` + arXiv API | 零配置 |
| Skill 入口 | Claude Code skill（Python 脚本） | 与现有工作流无缝集成 |
| 相似度计算 | TF-IDF 词重叠（本地计算） | 无需向量数据库，零额外依赖 |
| 笔记导出 | 标准 Markdown + YAML frontmatter | 兼容 Obsidian / Typora 等工具 |

## 开放问题（已解决）

| 问题 | 决策 |
|---|---|
| PDF 解析库选哪个？ | `pymupdf`，对学术双栏 PDF 效果最好 |
| 文献库默认路径？ | `~/.scholarmind/`，用户可通过 `config --set-lib-dir` 覆盖 |
| 语义相似度如何实现？ | v1 用 TF-IDF 关键词重叠；本地向量嵌入延至 P2 |
| Claude Code web_search 能下载 PDF 吗？ | 不能下载二进制文件；arXiv PDF 通过 `requests` 直接下载 |
| 是否支持 Semantic Scholar / PubMed？ | v1 仅支持 arXiv；其他来源延至后续版本 |
